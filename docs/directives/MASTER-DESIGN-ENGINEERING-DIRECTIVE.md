## 6. ANTI-AI-SLOP REQUIREMENTS

Audit all relevant public pages and administrative interfaces for generic AI-generated visual patterns.

Eliminate unnecessary badges, redundant labels, vague headlines, arbitrary purple gradients, excessive glow, gratuitous glassmorphism, repeated rounded cards, unnecessary decorative icons, predictable three-column grids, monotonous centered hero sections and filler content.

Do not wrap every section in a container.

Use visual hierarchy, proximity, whitespace, contrast, authentic imagery, editorial composition, optical alignment and carefully chosen accents.

Use appropriate concentric corner radii. Align mixed-size text and financial figures thoughtfully. Balance short headlines. Use tabular numbers where quantities, prices and financial statistics benefit.

Prioritize original compositions and real products, people, events, services and evidence.

Every decorative element must serve a defensible visual or functional purpose.

## 7. MOBILE-FIRST NON-NEGOTIABLES

Design around real mobile user journeys, not desktop layouts shrunk to fit.

Test representative widths including 320, 360, 375, 390, 414, 430, 768, 1024 and 1440 CSS pixels where applicable.

Implement generous 44–48px preferred touch targets, appropriate spacing, usable thumb-reach actions, safe-area handling, dynamic viewport behavior, keyboard-friendly forms, meaningful input types, inputmode, autocomplete and enterkeyhint.

Ensure sticky elements do not cover content, form fields, keyboard focus or browser controls.

Support native scrolling, browser back behavior, expected navigation, responsive dialogs and appropriate scroll restoration.

Never disable pinch-to-zoom.

Provide alternatives to hover, drag, swipe and gesture-dependent interactions.

Use accessible one-time-code autofill where OTP authentication exists.

Ensure slow-network and lower-powered-device usability.

## 8. TYPOGRAPHY AND CONTENT DESIGN

Use approved brand-appropriate typefaces, restrained font families, responsive type sizing, appropriate line heights, semantic headings and readable contrast.

Use fluid typography where appropriate, balanced headlines, localized numbers and currency, tabular financial figures, meaningful labels and precise microcopy.

Avoid unnecessary uppercase text, arbitrary italic emphasis and decorative typography that damages readability.

Optimize font subsets, file formats and loading behavior.

Write specific, meaningful headings instead of generic AI marketing language.

Never invent testimonials, facts, prices, availability, business claims, financial information or approved owner content.

## 9. INTERACTION ENGINEERING

Every interactive component must define applicable default, hover, focus, pressed, selected, disabled, loading, empty, error and success states.

Implement rapid user feedback, appropriate skeleton loaders, stable image placeholders, clear error recovery, useful success confirmation, safe retries and prevention of repeated submissions.

Implement optimistic updates only for reversible, low-risk operations with reconciliation and rollback.

Financial transactions, payments, booking confirmations and authoritative order states must never be falsely confirmed optimistically.

Use idempotency and server-side validation where duplicate submissions or transactional integrity require protection.

Preserve non-sensitive form progress safely. Never persist payment credentials or unnecessary sensitive information in browser storage.

Use stale-while-revalidate, pre-rendering, caching and prefetching only where technically and operationally appropriate.

Evaluate command palettes, keyboard shortcuts, undo notifications, accessible bottom sheets, expanded hit areas and advanced menu interactions where genuine user needs justify them.

Never implement advanced interactions simply to increase feature count.

## 10. MOTION DESIGN SYSTEM

Motion must communicate state, hierarchy, spatial continuity, causality or meaningful brand storytelling.

Establish consistent motion tokens. Suggested starting ranges are 80–120ms for immediate feedback, 120–220ms for small interactions, 180–350ms for component transitions and 250–450ms for suitable page transitions.

Use natural easing, interruptible animations and reversible state transitions.

Prefer transform and opacity animations where appropriate. Avoid unnecessary layout thrashing, continuous animation loops, excessive GPU layers and expensive paint operations.

Use CSS for simple interactions. Use the native View Transition API or existing animation libraries selectively with appropriate feature detection and fallbacks.

Consider Motion for shared layouts and interactive React animations. Consider GSAP only where advanced choreography justifies it.

Respect prefers-reduced-motion throughout CSS and JavaScript. Essential content and functionality must remain available when animations are disabled or unsupported.

Never hijack scrolling, force splash screens, delay navigation for spectacle, permanently hide content behind animation initialization or animate critical transactional information unnecessarily.

## 12. PERFORMANCE AND ACCESSIBILITY

Respect every project's existing performance budget, especially stricter project-specific constraints.

Target good Core Web Vitals:

- LCP: 2.5 seconds or less.
- INP: 200 milliseconds or less.
- CLS: 0.1 or less.

Distinguish field measurements from laboratory measurements.

Aim for Lighthouse mobile performance of 95+ and accessibility, best practices and SEO of 100 where realistically achievable. Never fabricate measurements or treat Lighthouse alone as proof of compliance.

Target WCAG 2.2 AA.

Implement semantic HTML, accessible names, visible focus, appropriate contrast, keyboard operation, accessible validation, screen-reader announcements, meaningful alternatives and reduced-motion support.

Optimize responsive images, image dimensions, LCP priority, lazy loading, font loading, route splitting, hydration, caching, query efficiency and third-party scripts.

Remove redundant dependencies and avoid adding multiple libraries that solve the same problem.

Maintain useful functionality under slow connections and partial feature support.
