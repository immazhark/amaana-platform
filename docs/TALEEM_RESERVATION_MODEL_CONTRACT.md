# Taleem reservation — unpublished synthetic model

AF-SPONSOR groundwork. Not production inventory or payment authorization. The existing programme catalogue is not a capacity catalogue and the published learner count is not available inventory. The model requires explicit synthetic units per programme per calendar month; 1/3/6/12 month terms and 1–50 units follow the current programme quote shape. A proposed hold can only be a candidate if every month fits. Expiry uses a supplied clock in integer epoch milliseconds; at expiry, a held record consumes no inventory, but a committed record still consumes its full term. Released rows remain identifiers, not availability promises. A replay must preserve all original request fields and cannot extend a hold; an expired request is refused. Missing or inconsistent data fails closed. The algorithm is O(C + 12R) expected time, O(C + R) space, with bounded input collections. It is pure, uses no clock, datastore, identity or provider, and is advisory only: concurrent callers can both see the same available capacity. Do not expose a route, persist a hold, derive actual places, link a student, reserve payment inventory, consume provider callbacks, or activate expiry jobs from this model. A future separately approved design must establish capacity ownership, atomic transaction/concurrency protection, duration and expiry policy, renewal/refund/cancellation and late-payment handling, auditable idempotency and privacy boundaries before implementation. No real reservation or sponsorship obligation has been created.
